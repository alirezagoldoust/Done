Yes. I’d structure this as a **board-centric task manager** rather than a generic CRUD app: visually closer to a polished Trello/Jira hybrid, but with a much simpler mental model.

* position is persisted

### Ordering

Test:

* move within same cell
* move to another cell
* move to beginning
* move to end
* move between two tasks

Frontend tests should cover important interactions where practical.

# 49. Drag-and-Drop Architecture

Design the board around:

```text
DndContext
  └── Board
       ├── StatusRow
       │    ├── TaskCell
       │    │    ├── SortableTask
       │    │    ├── SortableTask
       │    │    └── ...
```

Each task should have a stable draggable ID.

Each cell should have a stable droppable ID.

Avoid DOM-index-based identifiers.

When a drag begins:

* record the original location
* visually elevate the dragged task
* display a DragOverlay

When dropped:

* determine destination cell
* calculate ordering
* optimistically update UI
* call backend
* rollback if necessary

# 50. Modal Behavior

Use a proper accessible dialog component.

Task editing should support:

* Escape to close
* autofocus title when appropriate
* keyboard navigation
* loading state during save
* disabled save button while saving
* unsaved-change protection
* delete confirmation

Deletion should require confirmation.

Example:

```text
Delete task?

This cannot be undone.

Cancel     Delete
```

* smooth modal transitions
* smooth drag transitions
* carefully chosen typography
* compact controls

Avoid:

* excessive rounded cards
* excessive shadows
* excessive gradients
* excessive glass effects

# 52. Desktop Board Interaction

The board should occupy almost the entire available viewport.

Avoid unnecessary page scrolling.

Prefer:

```text
App shell
    ↓
Board header
    ↓
Scrollable board viewport
```

The board viewport should support:

* horizontal scrolling for columns
* vertical scrolling for tasks
* clear separation between header and board content

Consider sticky status labels/row headers if it improves usability.

---

# 53. Important Product Principle

Optimize for this workflow:

```text
Open board
    ↓
See everything
    ↓
Quickly create task
    ↓
Drag task as work progresses
    ↓
Click task when details are needed
```

A user should be able to manage their day without constantly opening dialogs.

The board itself should be the primary interface.
